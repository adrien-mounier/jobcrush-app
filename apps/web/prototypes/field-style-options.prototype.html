Four screens, four different field styles

This started as "the front door's fields don't match DESIGN.md". Reading the other stylesheets changed the question. The front door isn't an outlier, because there is no norm. Three corner radii, four text sizes, two fills and two focus treatments across four screens — and the field DESIGN.md describes exists nowhere in the product. Every value below is read from the shipped CSS.

Two things worth reading twice. Discovery's focus is a gold border — DESIGN.md forbids exactly that ("no glow, no border-colour tricks"), and a colour-only focus cue is the weaker one for anyone navigating by keyboard. And anything under 16px makes iPhone Safari zoom the page in when someone taps the field; there's no viewport restriction set, so discovery and the deck do that today, on the main journey.

What I'd do

One field style, everywhere — and it is nearly the doc's

10px corners · Night Raised fill · 16px text · 2px ink outline on focus

That is DESIGN.md's shape, DESIGN.md's fill and DESIGN.md's focus rule, with one reasoned exception on size: fields stay at 16px, because below that an iPhone zooms the page and the person has to pinch back out. The doc gains a line recording the exception and the reason — which is the honest version of a mismatch that is currently silent. The alternative fix, pinning the viewport so it cannot zoom, is an accessibility anti-pattern and should not be on the table.

  1. Don't bolt it onto #270. It touches four stylesheets and four screens on the main journey. That is its own ticket with its own QA gate, not a tail-end edit to a shipped one.
  2. Nothing changes on the front door today. The paste box matching its siblings is the right call until the siblings move too.
  3. The ticket's real payoff isn't tidiness — it's that discovery and the deck stop zooming on iPhone, and discovery's focus cue stops being colour-only.

The size question, at the size it matters

Both rooms are built from the real values and the product's own type stack, at phone width. The fields are live — click into one and type. Left is 16px as shipped; right is 14px as the doc currently specifies. This is the one number the recommendation departs from the doc on.

Why not the two obvious answers

Just update the doc to match the screens

  • There is no single set of values to write down. The doc would have to describe three radii and four text sizes, which is not a design system, it is an inventory.
  • It leaves discovery and the deck zooming on iPhone, and discovery's colour-only focus cue in place. Those are live defects, not stylistic drift.
  • The doc's own line is that a value outside the ramp is "drift, not idiom". This would make all of it idiom.

Just restyle the front door to match the doc

  • It would make the front door the only screen matching a doc nothing else matches — a fifth variant, so the product gets less consistent, not more.
  • It would newly break the one screen that currently doesn't zoom on a phone.
  • It fixes the smallest of the four inconsistencies and none of the two real defects.
